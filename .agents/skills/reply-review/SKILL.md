# 변경 검토 절차

## 입력

- 검토할 변경사항 또는 커밋 범위
- 저장소 루트의 AGENTS.md
- docs/agents/reviewer.md
- 관련 요구사항과 테스트 계획

## 절차

1. 저장소 루트를 확인하고 변경사항을 읽습니다.
2. docs/agents/reviewer.md와 변경에 관련된 명세만 선택해 읽습니다.
3. 실제 호출 경로를 따라 입력, 상태 변경, 생성, 발송, 재시작 처리를 추적합니다.
4. 아래 검토 항목 중 변경에 영향을 받는 부분을 확인합니다.
5. 가능한 결함은 합성 입력이나 Mock 재현으로 확인합니다.
6. 검토만 요청받았다면 파일을 수정하지 않습니다.
   수정도 이미 요청받은 작업에서는 오케스트레이터가 정한 범위로 처리합니다.
7. findings를 심각도순으로 보고하고, 근거 없는 추측은 별도로 표시합니다.

## 검토 항목

- 채팅방 또는 발신자를 잘못 식별했을 때 진행하는 경로가 있는가?
- 타이머 중, 생성 중, 전송 직전에 사용자가 답한 경우가 처리되는가?
- 전송 결과 미확정 상태에서 재시도하여 중복 전송할 수 있는가?
- 프로그램 재시작과 중복 이벤트가 기존 발송 기록을 무시하게 만드는가?
- 새로운 대화나 설정 변경으로 생성 결과가 오래되었음을 감지하는가?
- 말투 예시, 확인된 사실, 현재 상태, 봇 출력의 출처가 구분되는가?
- 상대 메시지에 포함된 지시가 설정·도구·수신자를 바꾸게 할 수 있는가?
- 로그·오류·fixture·문서에 실제 대화나 비밀값이 포함되는가?
- 자동 응답 활성화 및 중지 조건을 UI와 실행 코드가 동일하게 적용하는가?
- 테스트가 구현 내부를 그대로 따라 하는 데 그치지 않고 사용자 동작을 검증하는가?

## 결과 형식

각 finding에 문제, 영향, 재현 조건, 파일과 심볼, 수정 방향을 적습니다.
발견한 문제가 없으면 그 사실과 검토한 범위, 남은 검증 공백을 적습니다.
실행하지 않은 테스트를 통과했다고 보고하지 않습니다.
실제 카카오톡 발송으로 결함을 재현하지 않습니다.
