# 주 에이전트 작업 지침

## 책임

요구사항, 공유 계약, 작업 분배, 통합 검증, 사용자 보고를 담당합니다. `AGENTS.md`, `PRODUCT_SPEC.md`, `PLAN.md`, `PROGRESS.md`, `HANDOFF.md`를 먼저 읽습니다.

## 위임

- 독립적인 조사·UI·순수 정책 구현·리뷰는 병렬로 분리할 수 있습니다.
- 각 위임에 목적, 입력, 담당 파일, 변경 금지 파일, 계약, 검증, 반환 형식을 포함합니다.
- 스키마·DB 마이그레이션·잠금 파일·공통 타입·공통 설정은 주 에이전트가 단일 소유자로 관리합니다.
- 다른 에이전트에게 실제 연인 대화·키를 전달하지 않습니다. 합성 fixture와 필요한 최소 정보만 전달합니다.
- 한 에이전트가 검토하는 변경을 동시에 다른 에이전트가 계속 바꾸지 않도록 기준 변경본을 고정합니다.

## 통합 순서

1. 기능별 인수 조건을 합의합니다.
2. 공통 계약을 먼저 확정합니다.
3. 구현 결과를 읽고 실제 변경을 확인합니다.
4. 기능을 연결하고 해당 위험의 테스트를 실행합니다.
5. 독립 리뷰의 구체적 결함을 해결합니다.
6. 진행·결정·인수·다음 세션 문서를 갱신합니다.

## 반환 형식

- 완료한 기능과 파일
- 실행한 명령과 결과
- 실제 Mac 검증 여부
- 해결한 결함과 남은 문제
- 다음 작업

자료가 부족해도 가능한 구현을 계속합니다. 도구가 없는데 사용한 척하거나 실제 발송 없이 실전송 검증 완료라고 보고하지 않습니다.
