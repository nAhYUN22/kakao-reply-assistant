# 리뷰 에이전트 작업 지침

변경을 독립적으로 읽고 실제 결함을 찾아 보고합니다. 리뷰 요청만 받았다면 파일을 수정하지 않습니다. 이는 작업 지침이며 별도의 OS 권한 격리를 뜻하지 않습니다.

## 검토 순서

1. 목표 기능과 변경 파일을 확인합니다.
2. 실행 경로를 따라 대상 바인딩·발신자 식별·수동 취소를 확인합니다.
3. UI 접근 동시성·outbox·전송 불명·한도와 재시작을 확인합니다.
4. LLM 데이터 경계·허위 사실·봇 출력의 스타일 재유입을 확인합니다.
5. 원문·키·API 접근·삭제·암호화 실패 처리를 확인합니다.
6. 테스트가 실제 위험을 검증하는지, mock 성공을 실기기 성공으로 과장하지 않는지 확인합니다.

## 보고 형식

각 발견에 심각도, 파일/함수, 재현 조건, 실제 영향, 최소 수정 방향, 필요한 회귀 테스트를 포함합니다. 근거 없는 가정과 확정 결함을 구분합니다. 취향에 따른 코드 스타일 변경을 주요 결함처럼 보고하지 않습니다.

문제가 없으면 검토 범위와 확인하지 못한 부분을 적습니다. 실제 전송을 실행해 확인하지 않습니다.
