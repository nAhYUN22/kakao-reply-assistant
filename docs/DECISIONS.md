## 새 결정 템플릿

### ADR-015 / 2026-11-20 — M0/M1 모의 수직 기능의 실행 범위

- 기존 코드가 없는 명세 패키지이므로 Python 3.12/FastAPI와 React/TypeScript/Vite 구조를 채택했습니다. 설치 버전은 `uv.lock`, `frontend/package-lock.json`에 고정합니다.
- 첫 실행은 예제의 mock/off/실전송 false와 600초 지연을 유지합니다. UI의 명시적 모의 시작만 합성 대상과 데모 활성 구간을 설정합니다. 가짜 시계를 전진해 기다림을 재현하며 실시간 자동 감시로 표시하지 않습니다.
- M1에서 SQLite에는 본문 없는 작업·시도·중복 식별 메타데이터만 저장합니다. 합성 본문과 생성문은 메모리에만 두고 재시작하면 없어집니다. 실데이터 암호화·Keychain·보관 및 삭제 정책은 M2 이후 구현하며, 이 선택을 암호화 완료로 보고하지 않습니다.
- 실제 MCP/CLI와 외부 LLM은 이번 수직 기능에 연결하지 않습니다. 최종 제품의 실제 자동 발송 요구는 유지합니다. `docs/M1_API.md`가 UI/서버 통합 계약입니다.

### ADR-016 / 2026-11-20 — 로컬 개발 역할과 저장소 연결

- 공식 Codex 스킬 및 subagent 문서와 설치된 `codex-cli 0.152.1`, 현재 세션의 collaboration 도구를 확인했습니다. 템플릿으로 스킬 3개와 TOML 3개를 생성하고 구문 검증했습니다.
- 이번 세션은 생성 파일을 직접 읽어 지침을 적용하고 backend/frontend/reviewer를 실제 위임합니다. TOML 자동 발견이나 새 스킬의 자동 메뉴 등록을 검증했다고 주장하지 않습니다. 전역 설정·모델·승인 정책은 변경하지 않았습니다.
- backend 및 해당 테스트, frontend, 읽기 전용 리뷰로 책임을 분리했습니다. 공통 API·기존 JSON 스키마·잠금 파일·통합 검증·문서는 주 에이전트가 관리합니다.
- Git이 없었으므로 `main`으로 초기화하고 사용자 지정 GitHub URL을 `origin`으로 등록했습니다. 원격의 기존 브랜치가 없는 것을 확인했습니다. 강제 push와 원격 이력 덮어쓰기는 하지 않습니다.

### ADR-017 / 2026-11-20 — M2 암호화 선택과 복구 경계

- M1 기본 metadata-only를 유지하고 명시적 Keychain 선택 시 생성문을 AES-256-GCM으로 영속화합니다. 테스트는 EphemeralKeyProvider/주입한 가짜 backend만 사용합니다. 사용자의 실제 Keychain 키를 자동 생성하거나 읽지 않습니다.
- table/row/schema/key ID를 AAD로 인증하고 별도 키로 HMAC을 계산합니다. DB v1→v2 마이그레이션과 키 검증은 같은 트랜잭션입니다. 실패하면 기존 데이터와 버전을 보존하고 lock을 해제합니다.
- 암호화 DB의 키 참조/검증값을 저장해 재시작 시 키 누락·오류를 거부합니다. 운영 중 키를 다시 확인하며 생성문 저장·outbox 예약 실패 시 발송하지 않습니다.
- 7일 생성문 만료와 명시적 삭제는 본문/모의 전송기 복사본에 적용하고, 시도·중복 기록은 유지합니다. 30일 감사 정리는 tombstone과 복구 요구를 먼저 설계해야 하므로 미구현으로 남깁니다. 실시간 스케줄러도 후속입니다.
- v1 event ID 해시는 마이그레이션 후 중복 방지 연속성을 위해 유지합니다. 본문 해시가 아니며 live 원문 검색 키로 재사용하지 않습니다.

### ADR-018 / 2026-11-20 — 읽기 전용 MCP와 관측 보류

- 설치된 MCP Python SDK 1.30.0의 ClientSession/stdio를 사용하고 실제 프로토콜을 가짜 FastMCP subprocess로 검증합니다. kmsg 설치본은 없으므로 공식 고정 소스를 근거로 구현하되 실연결 완료로 보고하지 않습니다.
- kmsg MCP에는 채팅 목록 도구가 없습니다. 별도 확인된 catalog를 입력받으며 존재하지 않는 도구나 숨은 CLI fallback을 만들지 않습니다. 실제 대상 재확인 UI/수집 경로는 후속입니다.
- `kmsg_read`만 노출하고 background_safe=true, deep_recovery/trace_ax=false로 고정합니다. 한정된 프레임 relay와 프로세스 그룹 종료로 과대 출력/취소 뒤 고아 프로세스를 처리합니다. SDK 진단도 원문을 제거합니다.
- 최초/재연결 관측은 baseline입니다. 공백·오래된 스냅샷·모호한 중복/rollback은 재확인 전까지 정지합니다. 명시적 reset 후 다음 관측도 baseline입니다. `(me)`만으로 본인을 확정하지 않고 모든 관측의 authorship은 unknown으로 유지합니다.
- MCP 읽기를 모의 엔진에 자동 연결하지 않습니다. live 작성자/직접 답장/bot echo 증거와 프로세스 간 UI 조정이 남아 있습니다. 최종 자동 발송 범위는 M4에서 유지합니다.

### ADR-019 / 2026-11-20 — M2 병렬 역할과 공유 파일

암호화/키 공급자, MCP/관측, UI를 서로 다른 파일로 위임하고 독립 reviewer를 실행했습니다. 주 에이전트는 저장소·엔진·API·의존성·문서를 통합했습니다. 호스트 목록에서 프로젝트 스킬 3개 등록을 확인했고 reply-implement/reply-review를 적용했습니다. custom agent TOML 자동 선택 여부는 별도 미검증입니다.

### ADR-020 / 2026-11-20 — 사용자가 시작하는 실제 읽기 진단

설치본 kmsg 1.260921.0은 MCP에 목록 도구를 제공하지 않습니다. 로컬 UI에서 명시적으로 요청한 목록은 CLI에서, 선택한 1:1 대화의 관측은 같은 MCP 세션에서 수행합니다. 관측 가능한 목록만 선택에 사용하고 대상 재검사 및 사용자별 프로세스 잠금을 두 번의 읽기에 적용합니다. API는 대화 본문 대신 건수와 판정만 반환하며 서버는 읽기 결과로 작업을 만들지 않습니다. 실제 읽기 검증과 이후 자동 답장용 작성자 판별을 별도로 기록할 수 있습니다.

### ADR-021 / 2026-11-20 — 정확한 방 제목 조회와 선택적 전경 읽기

사용자가 창을 미리 열지 않고 기존 대화를 확인할 수 있도록 진단 API에 선택적 allow_open_window를 추가합니다. 생략하면 기존 background_safe 동작을 유지합니다. 이름은 목록에서 대상을 찾는 데 사용하고 MCP 호출에는 확인된 chat_id를 보냅니다. 단축·부분 이름을 임의로 한 사람에게 연결하면 다른 방이 열릴 수 있으므로 정확한 제목과 식별 근거를 확인합니다. 전경 모드에서는 kmsg가 창을 검색·열거나 닫을 수 있으며 자체 복구 동작도 가능합니다. 답장 발송·상시 감시는 별도 기능입니다.

근거는 [kmsg 1.260921.0 사용 문서](https://github.com/channprj/kmsg/blob/v1.260921.0/USAGE.md) 및 [서버 읽기 구현](https://github.com/channprj/kmsg/blob/v1.260921.0/Sources/kmsg/Commands/MCPServerCommand.swift)입니다.

### ADR-022 / 2026-11-20 — 목록 조회의 시간 한도와 오류 표시

실제 서버에서 12초 후 목록 조회가 실패한 사례를 근거로 기본 CLI 목록 대기는 30초, 개별 MCP 호출은 12초로 분리합니다. 목록을 얻지 못하면 일치하는 이름을 판단할 수 없으므로 시간 초과·출력 상한·잘못된 목록은 제한된 오류 코드로 구분합니다. 원문 오류는 표시하지 않습니다.

### ADR-023 / 2026-11-20 — 이름 직접 읽기의 단일 CLI 호출

실제 목록 조회가 행별 제목과 미리보기를 처리하는 동안 30초를 초과했고 사용자는 동일 터미널의 kmsg read가 빠르다고 확인했습니다. 이름 직접 읽기에는 CLI read 한 번만 사용하고, 목록 스냅샷·후보 선택·MCP 두 번 읽기는 사용자가 그 진단을 선택할 때 수행합니다. 직접 읽기는 사용자 지정 이름·결과 창 제목의 일치와 반환 구조만 확인합니다. 동명인 식별·메시지 영역 귀속·신규성은 증명하지 않으므로 자동 답장에 사용하지 않습니다.
