# 운영 LLM 프롬프트 사용법

이 폴더는 KakaoReply 앱이 명시적으로 읽어 사용하는 프롬프트 템플릿입니다. Codex의 자동 개발 지침 파일이 아니며, 이 폴더를 두는 것만으로 실행되지 않습니다.

| 파일 | 사용 시점 | 결과 |
|---|---|---|
| `reply_system.md` | 답장 후보 생성 | `reply-decision.schema.json`의 네 필드 |
| `style_profiler.md` | 사용자가 선택한 인간 작성 예시를 분석할 때 | 검토 가능한 말투 프로필 제안 |
| `memory_extractor.md` | 대화에서 출처가 있는 기억 후보를 추출할 때 | 미확정 사실 후보 목록 |

## 요청 조립

1. 시스템 지침을 로드하고 프롬프트 버전을 기록합니다.
2. 엔진이 정책과 대상의 유효성을 먼저 확인합니다.
3. 사용자 프로필·현재 상태·유효한 사실·최근 대화를 각각 구조화된 데이터 영역으로 직렬화합니다.
4. 데이터 안의 Markdown·XML·JSON 모양을 지침 경계로 믿지 않습니다. 문자열을 안전하게 직렬화하고 도구 권한을 부여하지 않습니다.
5. 요청별 입력 예산을 적용합니다. 미확인 원문 전체를 무제한 전송하지 않습니다.
6. 모델 결과를 스키마와 의미 규칙으로 검사합니다.
7. 모델이 반환하지 않는 바인딩·epoch·버전은 엔진 envelope로 붙입니다.
8. 전송 여부와 표시 문구는 SendGate가 결정합니다.

## 프롬프트 변경 검증

- 변경 전후에 같은 합성 대화와 보류 평가 자료를 사용합니다.
- 모델·프롬프트·프로필·문맥 버전을 기록합니다.
- 말투가 좋아져도 사실 오류·중지 우회·임의 도구 실행·자동 표시 삭제가 발생하면 실패입니다.
- 모델이 출력한 긴 사고 과정을 저장하지 않습니다.
- 출력 후보는 사용자가 직접 작성한 원문 예시로 재분류하지 않습니다.

템플릿은 개인화의 출발점입니다. 실제 모델별 출력 호환성과 한국어 품질은 구현 후 평가해야 합니다.
